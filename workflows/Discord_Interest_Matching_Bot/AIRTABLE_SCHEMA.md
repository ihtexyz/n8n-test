# Airtable Schema for Discord Interest Matching Bot

## Overview
This document describes the Airtable base structure required for the Discord Interest Matching Bot. Create a new Airtable base and set up the following tables with the specified fields.

## Table 1: Users

Stores user profiles and preferences for matching.

### Fields:

| Field Name | Type | Description | Options/Format |
|------------|------|-------------|----------------|
| `User ID` | Auto Number | Primary key | Auto-generated |
| `Discord ID` | Single Line Text | User's Discord ID | Unique |
| `Discord Username` | Single Line Text | Discord username | |
| `Email` | Email | User's email address | |
| `Full Name` | Single Line Text | User's full name | |
| `Location` | Single Line Text | City/Country | e.g., "San Francisco, USA" |
| `Job Title` | Single Line Text | Current job role | e.g., "Software Engineer" |
| `Company` | Single Line Text | Current company | |
| `Industry` | Single Select | Industry sector | Tech, Finance, Healthcare, Marketing, Education, etc. |
| `Hobbies` | Multiple Select | User hobbies | Hiking, Reading, Gaming, Cooking, Travel, Photography, etc. |
| `Interests` | Long Text | Free-form interests | Additional interests not in hobbies list |
| `Skills` | Multiple Select | Professional skills | JavaScript, Python, Design, Marketing, Sales, etc. |
| `Years Experience` | Number | Years of professional experience | Integer |
| `Timezone` | Single Select | User timezone | UTC-8, UTC-5, UTC+0, UTC+1, etc. |
| `Preferred Meeting Days` | Multiple Select | Days available | Monday, Tuesday, Wednesday, Thursday, Friday, Saturday, Sunday |
| `Preferred Meeting Times` | Multiple Select | Time preferences | Morning (8-12), Afternoon (12-5), Evening (5-9) |
| `What I'm Looking For` | Long Text | What user wants from matches | e.g., "Career advice, networking, collaboration" |
| `Created At` | Created Time | Account creation timestamp | Auto-generated |
| `Last Active` | Last Modified Time | Last profile update | Auto-generated |
| `Status` | Single Select | Account status | Active, Paused, Inactive |
| `Total Matches` | Count | Number of matches | Linked to Matches table |
| `Avg Rating Given` | Rollup | Average rating given to others | Average of Feedback ratings |

---

## Table 2: Matches

Tracks all user matches and their status.

### Fields:

| Field Name | Type | Description | Options/Format |
|------------|------|-------------|----------------|
| `Match ID` | Auto Number | Primary key | Auto-generated |
| `User 1` | Link to Record | First user in match | Links to Users table |
| `User 2` | Link to Record | Second user in match | Links to Users table |
| `Match Score` | Number | AI compatibility score | 0-100 |
| `Match Reason` | Long Text | AI explanation of match | Generated by LangChain |
| `Matched At` | Created Time | When match was created | Auto-generated |
| `Status` | Single Select | Match status | Pending, Scheduled, Completed, Cancelled |
| `Cal Link Sent` | Checkbox | Calendar link sent to both users | Boolean |
| `Meeting Scheduled` | Checkbox | Meeting time confirmed | Boolean |
| `Meeting Date` | Date | Scheduled meeting date | |
| `Meeting Time` | Single Line Text | Scheduled meeting time | e.g., "2:00 PM UTC" |
| `Meeting Link` | URL | Video call link | Zoom/Google Meet/etc. |
| `Meeting Completed` | Checkbox | Meeting took place | Boolean |
| `Completed At` | Date | When meeting occurred | |
| `Feedback Received` | Count | Number of feedback entries | Linked to Feedback table |
| `Avg Match Rating` | Rollup | Average rating for this match | Average of both users' ratings |
| `Discord Thread ID` | Single Line Text | Discord thread for this match | For messaging |
| `Notifications Sent` | Number | Number of reminder notifications | Integer |

---

## Table 3: Feedback

Stores post-meeting ratings and feedback.

### Fields:

| Field Name | Type | Description | Options/Format |
|------------|------|-------------|----------------|
| `Feedback ID` | Auto Number | Primary key | Auto-generated |
| `Match` | Link to Record | Associated match | Links to Matches table |
| `User` | Link to Record | User giving feedback | Links to Users table |
| `Rating` | Single Select | Overall meeting rating | 1 - Poor, 2 - Below Average, 3 - Average, 4 - Good, 5 - Excellent |
| `Conversation Quality` | Single Select | How useful was the conversation | 1, 2, 3, 4, 5 |
| `Would Meet Again` | Single Select | Would user meet this person again | Yes, Maybe, No |
| `Topics Discussed` | Multiple Select | What was discussed | Career, Hobbies, Projects, Industry, Personal, Other |
| `Comments` | Long Text | Additional feedback | Free-form text |
| `Submitted At` | Created Time | Feedback submission time | Auto-generated |
| `Meeting Duration` | Single Select | How long meeting lasted | 15min, 30min, 45min, 60min, 60+min |
| `Technical Issues` | Checkbox | Any technical problems | Boolean |
| `Match Partner` | Lookup | Who they met with | From Match record |

---

## Table 4: Interest_Tags (Optional)

Normalized interest/skill tags for better matching.

### Fields:

| Field Name | Type | Description | Options/Format |
|------------|------|-------------|----------------|
| `Tag ID` | Auto Number | Primary key | Auto-generated |
| `Tag Name` | Single Line Text | Interest/skill name | e.g., "Machine Learning" |
| `Category` | Single Select | Tag category | Technical, Business, Creative, Sports, Social, Other |
| `Usage Count` | Count | How many users have this tag | Linked to Users |

## Setup Instructions

### Step 1: Create Airtable Base
1. Go to [Airtable](https://airtable.com)
2. Create a new base called "Discord Interest Matching"
3. Delete the default table

### Step 2: Create Tables
1. Create each table listed above
2. Add all fields with the exact names and types specified
3. Configure select options for single/multiple select fields

### Step 3: Configure Relationships
1. Link **Matches.User 1** and **Matches.User 2** to **Users** table
2. Link **Feedback.Match** to **Matches** table
3. Link **Feedback.User** to **Users** table
4. Configure rollup fields for averages and counts

### Step 4: Create Views
Create useful views for managing the system:

**Users Table Views:**
- `All Active Users` - Status = "Active"
- `New Users This Week` - Created At is within last 7 days
- `Users Ready to Match` - Status = "Active" AND Total Matches < 5

**Matches Table Views:**
- `Pending Matches` - Status = "Pending"
- `Scheduled Meetings` - Status = "Scheduled"
- `Awaiting Feedback` - Status = "Completed" AND Feedback Received < 2

### Step 5: Get API Credentials
1. Go to [Airtable Account](https://airtable.com/account)
2. Generate a Personal Access Token with scopes:
   - `data.records:read`
   - `data.records:write`
   - `schema.bases:read`
3. Note your Base ID (found in API documentation for your base)
4. Note Table IDs or use table names in n8n

### Step 6: Configure in n8n
1. Add Airtable credentials in n8n
2. Use the Personal Access Token
3. Select your base and tables in the workflows

## Automation Rules (Optional)

Set up Airtable Automations for additional functionality:

1. **Welcome Email**: When new user is created → Send welcome email
2. **Match Notification**: When Status changes to "Scheduled" → Send confirmation email
3. **Feedback Reminder**: When Meeting Date is 1 day ago AND Feedback Received < 2 → Send reminder
